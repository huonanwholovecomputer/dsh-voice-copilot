# 小印复盘 2026-11-10：10 次工具失败 → 提示词与工具改动

数据来源：`python tools/learning_report.py --days 14`（5 会话 / 35 轮 / 207 次工具调用，失败 10，中途中断 6 轮，p95 93.6s，最长 674.7s）。

## 五个根因与对应的改法

| 现象 | 真因 | 改在哪 |
| --- | --- | --- |
| `wechat_find_attachment` 4 次里 3 次报 `ValueError: filename 必填` | 台账 `var/ledger.db` 只到上次 refresh（11-08 13:09），当天新文件查不到；且参数类错误被挂上「去查 wechat_status」的通用 hint，把模型带偏 | 桥 `mcp_server.py:655` 加 `_ledger_freshness()`，`mcp_server.py:705` 报错里直接写台账刷新时间 + 两条改法；`mcp_server.py:2306` 把 ValueError/TypeError/KeyError 的 hint 换成「这是参数问题，不是链路故障」 |
| `print_update_tab` 3 次报「未知成员: 某顾客」 | `owner_name` 只认三个店员成员，工具描述没写；`print_status` 只回人数不回名单，模型只能猜 | 工具描述写死「只认三名店员（A/B/C），顾客写 remark」；人设同名硬规矩（`cordis.patch.yml` persona 第 77 行） |
| `print_start` 之后想改备注 → `frozen` | 小印先出纸后补字段，顺序反了 | 人设第 75 行：出纸前把份数/页码/单双面/附加服务/备注全定稿，改错只能新开一页 |
| 11-08 那轮 674.7s / 46 步：`app_launch(wcda)` 说 launched 但进程秒退，白等 60+90s 才去 pwsh 排查 | `launch()` 只会轮询 probe，不判断「进程是不是已经自己退了」 | 桥 `app_launcher.py:405` 新增 `code=process_exited` 快速失败（实测 0.5s 返回，原来 30s）；人设第 43 行补「process_exited 不是没起来，别等别重复启动」 |
| 报「详细价格」每次 7 步 pwsh（65s / 53s），还吃过 401 | 控制口没有「取计费明细」的 op，只能手拼文本；token 头是 `X-Agent-Token` | 桥新增工具 **`print_price_detail`**（`mcp_server.py:1401`），自动对回订单号并按店主既有格式输出原文 |

另外两处：「份数不许默认 1 份」（人设第 44 行，源于 11-08 被连纠三次）；`wechat_messages` 补回 `quoteContent/quoteTitle/quoteType/quoteUsername`（`mcp_server.py:1560`），引用回复成了份数冲突的最强证据，不用再直连 WCDA API；`wechat_send_text` 按店主 11-10 22:02 的要求不再等数据库回读（`tools/kbd_send.py:520`，按键走完即 `state=sent`，只做 3 秒顺手核对并回 `db_confirmed`）——账本里这个工具的 p50 是 30.4s，大头就是等 `find_sent` 轮询落库，改完应在 4–5s。

语音噪声也进了人设（第 89 行）：开放麦克风会混进旁人对话，跟当前单对不上的金额/份数/人名当噪声丢掉，但不因此拦住已说清的指令。

## 验证

- 桥自检：`python selftest.py` → 全部通过（工具数 36→37）；`test_quote / test_ledger / test_printlist / test_printlist_mcp / test_contacts` 全绿。
- `print_price_detail` 在真控制口上跑通：tab 2 → `HN2026xxxx-xxxx` ¥1.60（与 11-10 手拼文本逐字一致）、tab 3 → `HN2026xxxx-xxxx` ¥1.10；空页直接报「这页没有文件」。
- 秒退路径用 `where.exe` 冒充验证过：0.5s 返回 `process_exited`，两个真程序仍回 `already_running=true`。

## 生效方式与下次对照

改的是桥（MCP 工具）和 persona（system prompt），**必须新开小印会话**才会加载；老会话不会热更新，也别恢复老会话（改 system prompt 会作废整段前缀缓存）。
