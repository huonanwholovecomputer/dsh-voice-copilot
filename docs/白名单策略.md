# 白名单策略：按订单来源圈定小印的检索范围

小印去微信里找文件时，只在白名单（`chats.excluded = 0`）的会话里找。会话是活的：顾客来来走走、群成员天天换，手工勾选很快就会过期。这套策略把「最近的订单是从哪些聊天来的」做成一个可重复的口径，一键算出该留谁、该排除谁。

## 判断流程

```
打印机日志 ──重建批次──► 最近的订单文件（时间 + 文件名）
                              │
台账 file_msgs ◄──按名对齐────┘  精确 → 归一化 → 去加工后缀
                              │
                    按会话汇总「近窗口供单份数」
                              │
chats 表 ──────────► 策略映射 ──► excluded / pinned 目标值
```

1. **重建订单**：从 `%APPDATA%\HN打印工具\logs\2026-*.log` 里找 `共 N 个任务待处理` 批次行，后面 `[i/N] 文件名` 就是这一批要打印的文件；`收到云端任务 #id: 文件名` 是网页 H5 上传单，单独标记。
2. **对齐台账**：文件名先精确匹配，再归一化（去扩展名、前导 `[xx]`、`^\d+_`、副本编号、空白），最后再去掉店主加工痕迹的后缀（打印版 / 最终版 / 修改版 / 扩充版）。匹配窗是打印时间往前 14 天、且只认打印前 120 秒内到达的消息，避免拿同名旧文件误判。
3. **判定供单**：`is_sent = 1`（店主自己发的）和「文件传输助手」不算顾客供单；名字前缀能猜出会话的只统计，不参与策略。
4. **映射白名单**：见下面三种口径。

## 三种口径

| 口径 | 群 | 私聊 | 适用 |
| --- | --- | --- | --- |
| `hybrid`（默认） | 只留近窗口**供过订单文件**的群 | 留台账里**有文件**的私聊 | 日常：群不进检索范围，私聊尽量不漏顾客 |
| `orders` | 只留近窗口供过订单的群 | 只留近窗口供过订单的私聊 | 最干净；会排除只发过照片/证明材料的家人朋友 |
| `files` | 台账里有文件就留 | 台账里有文件就留 | 最宽松；资料群会重新被拉回来 |

- 窗口默认 **10 天**，可调 1–120 天。
- `pinOrderChats`（默认开）：把近窗口供过订单的群置顶，方便一眼看到。
- 「文件传输助手」只要台账里有文件就始终保留。

## 不计入来源

这三类文件不会让任何会话被纳入白名单，因为它们证明不了「这个会话最近在给小印供文件」：

- **云端 H5 上传**：顾客从网页传的，没有微信会话；
- **微信图片**：台账只收 `renderType=file` 的文档，图片压根没进索引；
- **店主回传/加工件**：`is_sent = 1` 的文件是店主自己发的（[处理好的]…、_修改版 等）。

## 用法

### 页面（推荐）

小印 → 群聊白名单 → 展开「一键策略」：

- 选口径、窗口天数、是否置顶供单群；
- **预览方案**：只读，不写库，列出将纳入/将排除的会话和改动数；
- **应用方案**：先把当前 `excluded / pinned` 备份到 `~/.dsh/voice-copilot/whitelist-snapshot.json`，再写库；
- **撤销上次**：从快照恢复，备份文件随即删除。

### 命令行

```powershell
node tools/whitelist-strategy.mjs --ledger "D:\个人\WeChatDataAnalysis研究\var\ledger.db"
# 预览：群 2/68 纳入，私聊 80/162 纳入，可见文件 597/797，改动 1

node tools/whitelist-strategy.mjs --ledger "...\ledger.db" --days 14 --mode orders --apply
node tools/whitelist-strategy.mjs --ledger "...\ledger.db" --undo
node tools/whitelist-strategy.mjs --ledger "...\ledger.db" --json
```

| 参数 | 说明 |
| --- | --- |
| `--days N` | 订单窗口，默认 10 |
| `--mode hybrid\|orders\|files` | 口径，默认 `hybrid` |
| `--no-pin` | 不置顶供单群 |
| `--ledger PATH` | 台账路径，默认环境变量 `DSH_VOICE_COPILOT_LEDGER_DB` |
| `--log-dir PATH` | 打印机日志目录，默认 `%APPDATA%\HN打印工具\logs` |
| `--data-dir PATH` | 快照目录，默认 `~/.dsh/voice-copilot` |
| `--apply` / `--undo` | 应用 / 撤销 |
| `--json` | 输出方案 JSON |

### 代码里复用

```js
import { analyze, saveSnapshot, applyPlan, undoSnapshot } from './whitelist-policy.js'

const { plan, attrTotals, chats } = await analyze({
  dbPath: ledgerDb,           // 台账
  logDir: printerLogDir,      // 打印机日志
  days: 10,
  mode: 'hybrid',
  pinOrderChats: true,
})
// plan.changes 是有变化的会话；plan.totals 是统计
saveSnapshot(dataDir, chats)          // 写库前备份
await applyPlan(ledgerDb, plan)       // 只改 excluded / pinned
await undoSnapshot(ledgerDb, dataDir) // 回滚
```

### HTTP 接口

页面用的三个路由（挂在 `__dsh-voice-copilot` 下，走页面同源鉴权）：

- `GET  /ledger/policy?days=10&mode=hybrid&pin=1` — 预览，只读；
- `POST /ledger/policy/apply`，body `{ days, mode, pinOrderChats }` — 应用；
- `POST /ledger/policy/undo` — 撤销。

## 安全边界

- 只写 `chats.excluded` / `chats.pinned`，不增删会话、不重刷台账索引；
- 台账刷新（`bridge/ledger.py` 的 upsert）只更新 name / 预览 / 时间这些列，**不会覆盖** `excluded / pinned`，所以策略结果不会被刷新冲掉；被排除的会话刷新时直接跳过；
- 每次应用前自动备份，撤销即恢复；CLI 和应用接口都走同一份 `whitelist-policy.js`，页面和命令行结果一致。

## 一个实测例子（2026-11-06）

10 天窗口、hybrid 口径：

- 打印批次 218，文件 405 次：云端 99、私聊 187、群聊 24、店主回传 18、图片 17、未归因 38；
- 群 2/68 纳入；私聊 80/162 纳入；可见文件 597/797；
- 唯一改动：排除某个只发学习资料的班级群——台账里有 6 份文件，但近 10 天没有供过订单文件。这正是 hybrid 的取舍：它的价值是老资料，不是最近的订单来源。想保留这类资料群，用 `--mode files`（会更宽松），或手工取消勾选。

## 已知局限

- 日志不完备：云端 403 时只有本地临时号、没有云端订单行；云端单没有微信会话，只能归到「云端」；
- 图片无法归因（台账不收图片），会显示为「图片」而不是某个会话；
- 归一化只能吸收常见的改名，店主手工重命名得面目全非的文件会落到「未归因」；
- 台账只索引最近扫描到的窗口（约 200 条/会话级别），很久以前的老文件可能查不到，这类会话会被判成「近窗口未供单」。
